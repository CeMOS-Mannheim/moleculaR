# Cardinal migration change log

This is the chronological record of every migration step. Scientific decisions
are recorded separately in `scientific-decisions.md`. Entries distinguish completed
work from validation still outstanding.
Confirmed and suspected legacy defects are tracked separately in
[`legacy-bugs.md`](legacy-bugs.md) for repairs in a separate legacy working copy.

## 2026-11-23 — Step 3: Cardinal import and single-analyte extraction

- Added `R/readMsi.R`: file-backed default import, file-pair and option checks,
  metadata preservation, optional exact run selection, strict integrity errors
  when `check = TRUE`. Existing legacy import remains available.
- Added `R/msi-accessors.R`: native class, coordinate, run, pixel-count,
  pixel-subset, and input-state validation helpers.
- Added `R/msi-extractIon.R`: strict FWHM windows, Gaussian/sum/mean/max
  aggregation, serial chunked spectra access, selected feature rows for shared
  axes, independent nearest-mass confirmation, and existing point-pattern output.
- Updated `searchAnalyte()` to dispatch Cardinal inputs to that implementation;
  preserved the legacy sparse algorithm and empty-ppp convention. Unchanged:
  `probMap()`, spatial constructors, `gaussWeight()`, and FWHM models.
- Updated DESCRIPTION dependencies and Collate; added testthat harness and
  extraction, import, and seeded spatial regression suites. Regenerated exports
  and help using roxygen2. Excluded local reference materials and development
  documentation from package builds.
- Validation: all three new test files pass. Equivalent aligned numerical
  spectra reproduce legacy aggregation and seeded MPM scientific fields at
  tolerance 1e-10; default FTICR predictions are preserved. File-backed and
  in-memory processed/continuous imports and native backed types pass.
- Explicit numerical changes: strict boundary fixture sum is 12 versus legacy
  20 (one outside-window peak of intensity 8). Unaligned observed-peak means
  use the documented denominator; a fixture with one peak gives 3 versus the
  shared-axis mean 1 over three features.
- Initial failures revealed actual namespace exports (`centroided` is exported
  by ProtGenerics), Cardinal array subsetting behavior, normalization scaling,
  and warning-only binary integrity checks. Corrected implementation/tests and
  recorded D007. All affected cases were rerun successfully.
- Remaining: package installation/checks, environment validation/lockfile,
  first-milestone performance measurements and report. Batch searches, measured
  FWHM migration, preprocessing, Shiny, cleanup, and large-scale validation are
  later stages and are not yet supported by the new Cardinal path.

## 2026-11-23 — Step 4: reproducibility and initial performance validation

- `BiocManager::valid()` returned TRUE for the isolated library. Updated
  `renv.lock` after validation, including the selected Bioconductor 3.23 release,
  runtime/test/documentation dependencies, and official Bioconductor package
  source records. The old lockfile is preserved in the legacy branch.
- Added environment validation, test-summary export, package-check, and fresh
  process benchmark scripts; recorded `environment.txt`, `test-results.csv`,
  and `first-milestone-benchmark.csv`. Ignored local renv working state.
- All 241 assertions across 12 tests pass with no test warnings, skips, or
  failures. Package build and installation passed; the first R CMD check
  stopped at DESCRIPTION checking because inherited C.UTF-8 locale settings
  cause startup errors on Windows. Rerunning with C locale explicitly set.
- Real-data benchmark: 24,504 pixels, 681,849,892-byte ibd, 59,735,434-byte XML;
  file-backed import 1.73 s, extraction 10.16 s, repeat 10.35 s, 17,646 detected
  pixels, 7,180,208-byte Cardinal object. R process peak working set
  1,494,827,008 bytes (whole session, including import and package/data loading).
  No single R allocation >= 1 MB was recorded during the repeat extraction.
- Limitations found: the legacy exported processed example has per-spectrum
  centroid tags but lacks the file-level tag used by Cardinal, so extraction
  correctly rejects its unknown status. Used the original file with explicit
  file-level centroid status for the benchmark; no input files were modified.
  Cardinal warns about an unrecognized scan-direction ontology term in that
  file. Default import retains Cardinal's metadata conversion behavior.
- Memory improvement over legacy is not yet established. Whole-process peak
  memory includes substantial XML/object overhead; larger-scale measurements
  and legacy performance comparisons remain phase 7 work.
